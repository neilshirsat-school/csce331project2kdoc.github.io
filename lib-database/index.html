Database Layer

lib-database owns everything that touches PostgreSQL: the Exposed table definitions, SQL query builders, repository implementations, schema bootstrap, and operational reports. It depends on lib-logic for domain types but never on JavaFX.

Responsibilities

  • Build and validate PosDatabaseConfig from environment variables.

  • Execute transactions through PosDatabase.

  • Bootstrap the schema and seed data with PosBootstrap.

  • Provide Exposed Table definitions for every relation.

  • Expose repository classes used by the cashier and manager shells.

  • Keep compatibility with older schemas by probing for optional views and columns.

Design conventions

  1. One transaction per operation. Repositories use database.transaction and never leak JdbcTransaction instances.

  2. Schema probes, not migrations at runtime. Optional tables are detected with information_schema before use.

  3. Prepared statements for values. SQL builders interpolate only validated identifiers and use parameters for user data.

  4. Stable public ids. Rows carry an internal integer key plus a public NanoID used by receipts and URLs.
